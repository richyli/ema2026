M 工具箱分享

2026 EMA — AI 與媒體

第 1、2、3、4、7、8、10、13、15 週🗣 分享15′草稿跨課共用：EMA、AICreativity、GCIT、Product、WebAnalytics、InfoViz

15 分鐘小模組（sharing）。跨課共用、每週輪替。本模組整段就是分享與互評，無 lecture。

🎯 學習目標（學完你能）

每條目標都是「一項能力 → 能解釋一個真實問題」。這是分享互評模組，目標是把一場學生分享變成全班可帶走的資產。目標由淺入深排列（Bloom 認知階層由低到高）。

# Bloom 層級 你會的能力 讓你能解釋的真實問題
1 應用 用三段式（解決什麼問題／怎麼做＋demo／一個坑）講清楚自己的一個小產出 為什麼「我做了一個超完整系統」的吹噓不值錢，「我本來很煩、後來一個小撇步省半小時」才值錢？
2 分析 用快評三問（我會用嗎／哪裡可再省力／有沒有更好的工具）拆解別人的工具能不能搬到自己場景 這個工具搬到我的工作上，要改哪裡才能用？——把它接回自己的場景，才不是空泛稱讚。
3 評鑑 判斷一個分享的工具自己能不能複製成功，並回報 本質金句：沒有坑的分享是廣告，有坑的分享才是教材。拿走 prompt 可以，但換個情境你知道要改哪一句嗎？不知道就只是複製貼上、沒真正學到（cognitive offloading）。

對齊說明：目標 1 由「分享段：盯三段式結構」帶出；目標 2（分析層）由「快評段：固定三問」帶出；目標 3（評鑑層）由「歸檔＋反思：聽眾挑一個別人的工具實際試用、下次回報能不能複製成功」檢核，難度對得上評鑑層。

  • 核心：1–2 位學生分享本週做的小產出（skill／prompt／工作流／工具），全班 1 分鐘快評。
  • 目的：累積班級共用工具箱；同學/資深主管彼此的實務是重要教材。
  • 期末彙整成個人 + 班級 AI 工具箱。

進行方式（15′）

  • 分享（每人 3–4′）：講「解決什麼問題 → 怎麼做 → 一個踩到的坑」，現場 demo 30 秒。
  • 快評（每人 1′）：台下用固定三問回饋——「我會用嗎／哪裡可再省力／有沒有更好的工具」。
  • 歸檔（1′）：分享者把作品丟進班級共用工具箱（Notion／共用資料夾），標題加一句話用途。

💬 反思（內建）

  • 分享者本週回去寫一行：「這次分享後，有人給我哪個我沒想到的改法？」
  • 聽眾本週挑一個別人分享的工具實際試用，下次回報「能不能複製成功」。

輪替排程由各課課綱安排；本模組可獨立 15′，也可併入其他 45′ slot 的尾段。

📚 詳細上課內容

這是 15′ 分享型小模組，沒有 lecture。老師的角色不是「講者」而是「主持人」——你的工作是讓一場學生分享變成全班可帶走的資產。以下逐段要點，照著主持即可。

一、逐段講稿要點（15′ 三段：分享 → 快評 → 歸檔）

開場破冰（30″，每次固定流程化） - 開場句：「我們又到了工具箱時間。提醒一下，這裡分享的不一定要很厲害，越是『我本來很煩、後來用一個小撇步省下半小時』的東西，越值錢。」 - 破冰的關鍵是降低分享門檻：明說「不接受『我做了一個超完整系統』的吹噓，我們要的是一個能複製的小動作」。資深主管班（EMA）要特別強調：「你二十年的實務直覺，配上一個 prompt，就是別人三年的捷徑。」 - 轉場句：「OK，今天先請 ___ 來，給你 3 分鐘。計時開始。」（當場開計時器，建立節奏感）

分享段（每人 3–4′）——盯緊三段式結構 - 這段老師幾乎不講話，但要在分享者跑題時拉回結構。標準結構是三句話： 1. 解決什麼問題（痛點）：「你原本卡在哪？這件事一週發生幾次？」——逼出頻率，頻率高才值得做成工具。 2. 怎麼做（方法 + 30″ demo）：實際把 prompt／工作流秀出來，不是用講的。轉場提醒句：「直接 demo 給我們看，不要念稿。」 3. 一個踩到的坑（限制）：「這個工具什麼時候會壞掉、什麼時候不能用？」——這是最容易被略過、卻最有教學價值的一段。老師若發現分享者跳過，補一句：「等等，你一定有踩過坑，講一個，這比成功的部分更有用。」 - 主持人心法：分享者講完「怎麼做」就想坐下時，務必追問那個坑。沒有坑的分享是廣告，有坑的分享才是教材。

快評段（每人 1′）——固定三問，全班輪流 - 轉場句：「謝謝。台下用我們的三問來回饋，不要客套，講真的。」 - 三問釘在投影片上，隨機點 2–3 位同學各答一問： 1. 「我會用嗎？」——逼聽眾把它接回自己的工作場景，不是空泛稱讚。 2. 「哪裡還可以再省力？」——把分享變共創，常常台下一句話就讓工具升級。 3. 「有沒有更好的工具做同樣的事？」——避免全班鎖死在一個工具上。 - 老師收尾句：「剛剛 ___ 提的那個改法，___（分享者）你回去試試，下週回報。」——當場指派 follow-up，讓快評不是講完就忘。

歸檔段（1′）——當場做完，不要拖到課後 - 轉場句：「趁現在，把它丟進工具箱，標題加一句話用途。沒丟進去的不算分享。」 - 規則化：分享者當堂把作品貼進班級共用空間（Notion／共用資料夾），標題格式固定：【動詞＋對象】一句話用途，例如「【轉換】會議逐字稿→三段式摘要」。 - 收尾總結句：「我們的工具箱又多了一格。期末你們每個人手上會有一本全班共同養出來的 AI 工具書。」

二、wiki 真實案例 / 引用

  • 講「分享 prompt 的價值與風險」用 cognitive offloading：分享一個好 prompt，本質上就是把一個「認知卸載工具」傳給全班——別人不用再從頭想怎麼問 AI。引 Koh & Doroudi（2023）的提醒：適度卸載釋放認知資源，過度卸載則「沒真正學到東西」。教學點轉化：「我給你 prompt 是讓你省力去想更難的問題，不是讓你變成不思考的複製貼上機。用之前先問自己：我懂它為什麼這樣寫嗎？」可帶 Lodge 的二維類型學（個人/協作 × 卸載/延伸）讓學生分類自己分享的工具。
  • 幫學生判斷「我的工具屬於哪一類」用 prompt engineering：引 Holmström & Carroll（2024）的五種商業應用——problem-solving／market research／content generation／decision support／prototyping and design。快評時可請聽眾順手歸類：「___ 這個逐字稿摘要 prompt 屬於 content generation 還是 decision support？」幫全班建立共同語言，也讓工具箱可以分類。同筆記也支援：prompt 不是一次到位，Midjourney 平均要 7.8 步迭代——拿來安慰「第一版 prompt 很爛是正常的」。
  • 講「好 prompt 長什麼樣」用 creativity/prompts：這是現成的學生用 AI prompt 模板庫，三段式結構（角色設定＋任務＋輸出格式）。當有人分享的 prompt 寫得鬆散，直接把這個範本投出來對照：「你看，好的 prompt 通常有這三段，你的缺了輸出格式那段，所以結果才不穩。」
  • 講「人在前後端、prompt engineer 是新職業」用 Davenport Mittal 2022 How Generative AI Is Changing Creative Work：支援「分享 prompt 本身就是一種專業技能、值得累積」的論點（HBR，少量範例微調、人類在前後端）。
  • 講「何時放手給 AI、何時人接手」用 adaptive autonomy：當有人分享高度自動化的工作流（整段交給 AI 跑），用「能沿自主刻度滑動比固定高/低自主更好」提醒：好工具要留人接手的檔位。對應 vibe coding 的放手時機。
  • 進階批判視角（選用）：Caramiaux 2025 Generative AI Creative Work Narratives、Bender 2025 Generative AI Creative Labour 可在分享涉及「AI 取代某段創意勞動」時，丟一句反思：採用工具的同時，我們交出了哪一塊判斷權？
  • 工具操作層（Claude Code／MCP／vibe coding）wiki 無素材，改用自建 Case 案例：這層本來就無論文，正常。示範「把工作流產品化」用 Case - GTM Engineering at Anthropic（不會寫程式的人把工作流產品化）；示範「驗證者跑新 context 確認可複製」用 Case - Claude Build Day Hackathon；示範「與 AI 互動的原則 + 領域知識護城河」用 Case - Opus 4.7 Claude Code Hackathon。這三個 Case 正好對應快評三問裡的「能不能複製成功」。

三、投影片要點 / 板書

投影片 1：分享格式範本（釘整堂） - 三段式，大字：① 解決什麼問題（頻率？）→ ② 怎麼做（含 30″ demo）→ ③ 一個踩到的坑 - 底下一行小字：「沒有坑的分享是廣告，有坑的分享才是教材」

投影片 2：快評三問（釘整堂） - 我會用嗎？（接回我自己的場景） - 哪裡還可以再省力？ - 有沒有更好的工具做同樣的事？

投影片 3：班級工具箱欄位（歸檔模板） - 標題：【動詞＋對象】一句話用途 - 欄位：分享者 ｜ 解決的問題 ｜ 工具/平台 ｜ Holmström 分類（problem-solving／market research／content generation／decision support／prototyping）｜ 一個坑 ｜ 連結/檔案 - 一句話：「標題寫不清楚的，下週沒人找得到。」

板書（隨堂寫，一條軸線） - 在白板畫一條橫軸：左端「全交給 AI（卸載）」← → 右端「全自己來」，中間標「人接手的檔位」。每個分享的工具請分享者來貼一個點（呼應 adaptive autonomy 與 cognitive offloading）。

四、活動與討論造稿

活動 A：老師示範一場完整分享（第一次跑此模組時必做，約 4′）

第一次上這模組，學生不知道「好的分享長怎樣」，老師先親自示範一遍，邊做邊把結構講出來：

  • 題目（假想例）：「我做了一個會議逐字稿轉摘要的 prompt。」
  • 逐步演示：
  • 「解決什麼問題」——「我每週開三次會，事後整理紀錄要花 40 分鐘，而且常漏掉誰被指派了什麼。」（強調頻率：一週三次 → 值得做成工具）
  • 「怎麼做 + demo」——投出實際 prompt，現場貼一段逐字稿跑給大家看。prompt 結構刻意對齊 creativity/prompts 的三段式：
    • 角色：「你是一位會議祕書」
    • 任務：「把以下逐字稿整理成三段：① 決議事項 ② 待辦與負責人 ③ 待釐清問題」
    • 輸出格式：「用表格列待辦，每列含負責人與期限」
  • 「一個踩到的坑」——「逐字稿如果語音辨識把人名打錯，AI 會把待辦指派給錯的人，所以我一定會人工核對負責人那一欄。」（呼應 adaptive autonomy：高自動化流程要留人接手的檔位）
  • 演示完，老師自問自答「預期台下會問什麼」，把快評三問示範一遍：
  • 「我會用嗎？」→ 「常開會的人會，不開會的人不會——所以這工具不是萬用，是給特定情境的。」
  • 「哪裡可以再省力？」→ 「可以接一個自動把待辦丟進行事曆的步驟，但那需要 MCP/串接，先不做。」
  • 「有沒有更好的工具？」→ 「有些會議軟體內建摘要，但客製化不如自己寫 prompt——這是取捨。」

活動 B：真人分享輪替（本模組主體） - 步驟：① 開計時器，分享者 3–4′ ② 老師盯三段式、必要時追問那個坑 ③ 隨機點名 2–3 人跑快評三問 ④ 當堂歸檔 - 給聽眾的提問（投影提示）：「先別評好不好，先想：這個工具搬到你的工作上，你要改哪裡才能用？」——把快評從「評審」變成「試裝」。 - 常見錯誤與引導句： - 錯誤一：分享者只秀成果不秀過程 → 引導句：「倒帶，給我們看你實際輸入了什麼。」 - 錯誤二：跳過坑 → 引導句：「你一定撞過牆，講一個失敗的例子，這對大家最有用。」 - 錯誤三：台下只會說「好厲害」→ 引導句：「『厲害』幫不了你。用三問之一，講具體的。」 - 錯誤四（卸載陷阱）：有人想直接抄走 prompt 卻不懂原理 → 引導句（扣 cognitive offloading）：「拿走可以，但你要能改它。如果換個情境，你知道要動哪一句嗎？不知道的話你只是在複製貼上，沒真正學到。」

收束討論（最後 1′，扣理論） - 引導句：「我們今天又往工具箱丟了 ___ 個工具。回去做兩件事：分享者寫一行『有人給我哪個我沒想到的改法』；聽眾挑一個別人的工具實際試一次，下週回報『能不能複製成功』。」 - 一句話總結（扣 prompt engineering 的 7.8 步迭代）：「沒有人第一版就完美，工具是被全班一起改出來的——這就是為什麼我們要公開分享，而不是各自藏招。」
