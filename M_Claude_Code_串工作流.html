2026 EMA — AI 與媒體

第 4 週✋ 實作45′草稿跨課共用：EMA、Product、WebAnalytics

45 分鐘完整模組（practice）。跨課共用。

先修 M Claude Code 上手（已會安裝、會下三段式指令、懂 skill／hook／MCP 概念）。

🎯 學習目標（學完你能）

每條目標都是「一項能力 → 能解釋一個真實問題」。學這個不是為了多會一個功能，是為了把你每週都在重複做的爛事，包成一個一鍵叫用、還能自己接資料的流程。目標由淺入深排列（Bloom 認知階層由低到高）。

# Bloom 層級 你會的能力 讓你能解釋的真實問題
1 理解 說明 skill＝可重複的固定流程、MCP＝接外部資料源的轉接頭 為什麼有了 skill 我就不用每週把同一串指令重打一遍？為什麼沒有 MCP，它只看得到我資料夾裡的檔？
2 應用 設計並做出一個自己的 skill（週報彙整／選題評估／查證清單），必要時用 MCP 接資料 我每週都在做的哪件事，最值得包成 skill？本質金句：值得做成 skill 的＝頻率高、步驟固定、輸入輸出講得清楚。
3 分析 判斷一個 skill 為什麼跑歪——是 prompt 不夠明確，還是資料沒真的接上 為什麼別人照我的 skill 跑，結果卻不一樣？——拆開來看，多半是 prompt 留白讓 AI 自作主張，或它根本沒接到資料源、只是純文字模板。

對齊說明：目標 1 由「15′a 設計 skill 的步驟＋15′b MCP 示範」帶出；目標 2 由「15′c 動手做 skill」帶出、由小作業「做出一個可分享的 skill」檢核；目標 3（分析層）由配對互評「prompt 夠明確嗎／有沒有真的接到資料源」帶出，由個人反思「標出它最可能卡住的地方（prompt 還是資料）」檢核，難度對得上分析層。

  • 核心：設計個人 skill；用 MCP 接資料源（試算表、政府開放資料、檔案）；批次產製多版本。
  • 15′ a：設計一個 skill 的步驟。
  • 15′ b：MCP 接資料源示範。
  • 15′ c：動手做自己的 skill。
  • 小作業：做出一個自己的 skill（週報彙整／選題評估／查證清單），寫成可分享說明。

💬 討論／分享／反思（10′）

  • 配對互評（~5′）：兩人一組，互看對方剛動手做的 skill。重點問三件事：這個 skill 解決的是哪個會「重複做很多次」的工作？prompt 寫得夠明確、別人照著跑會不會跑歪？有沒有真的接到資料源（MCP／試算表／開放資料），還是只是純文字模板？
  • 全班收斂一題（~3′）：哪一類工作最值得做成 skill？大家丟出自己想自動化的場景，一起判斷「值得做成 skill」的判準：頻率高、步驟固定、輸入輸出可描述。
  • 寫下個人反思（~2′）：寫一句話，回答「我下週會把哪一件每週都在做的事，包成自己的第一個 skill？」並標出它最可能卡住的地方（是 prompt、還是資料接不上）。

📚 詳細上課內容

本模組是 M Claude Code 上手 的進階接力：上週學生已經把 Claude Code 跑起來、會下三段式指令、聽過 skill／hook／MCP 三個比喻。這週不再重教安裝，直接往前蓋——把「上週手動跑一次」的東西，變成「一鍵叫用、還能自己接資料、還能一次產出多版本」的個人工作流。對象設定為管理／編務職的學生：他們每週都在做一串重複的爛事（彙整週報、評估選題、查證清單），這堂課就是把那串爛事固化掉。老師看著下面要點就能講。

① 逐段講稿要點

15′a — 設計一個 skill 的步驟（要說什麼、容易卡在哪）

開場定錨（1′） - 一句話接上週：「上週你已經能讓 Claude Code 跑一件真實工作了。但你有沒有發現——同一串指令，你這週重打一遍、下週又重打一遍？今天就是要把那串重複的指令，固化成一個一鍵叫用的東西，它叫 skill。」 - 預告本質：「上週的口令是『下指令＋驗收』，今天升一級——把你下過、驗收過、確定好用的那串指令，存起來變成可重複的流程。」

什麼值得做成 skill（4′） - 先講判準，再動手。三條判準（板書同步）： 1. 頻率高——你每週、每天都在做（一次性的事不值得固化）。 2. 步驟固定——流程大致一樣，不是每次都長得不同。 3. 輸入輸出講得清楚——你能描述「丟什麼進去、要吐什麼出來」。 - 反例校正：「『幫我想一個 idea』不適合做成 skill——它步驟不固定、輸出也說不清。『把這週五篇稿子彙整成一頁主管週報，每篇三行、附連結』就非常適合——頻率高、步驟固定、輸入輸出一句話講得完。」 - 本質金句：值得做成 skill 的＝頻率高、步驟固定、輸入輸出講得清楚。

主管場景 worked example：週報彙整（6′） - 帶全班一起拆一個真實場景，示範「怎麼把腦袋裡的流程描述出來」。挑「週報彙整」當主例（也可換成選題評估／查證清單，下方各給一句）： - 背景（角色＋脈絡）：「你是我的編務助理。每週五我會給你這週發布的稿子清單。」 - 任務（步驟講死）：「① 逐篇抓出一句話重點；② 標出哪幾篇數據表現最好；③ 彙整成一頁，每篇三行以內、附原文連結；④ 最後給我三句『下週選題建議』。」 - 格式（輸出長相）：「用 Markdown，主管掃一眼就懂，控制在一頁。」 - 老師示範把這三段存成一個 skill（給它取名 週報彙整），下次只要喊一聲名字＋丟清單，整套就跑。 - 另兩個場景一句話帶過，讓不同職務的學生都對得上： - 選題評估：背景＝「你是選題會的幕僚」；任務＝「對每個提案打三個分（時效／獨家性／可執行性），各一句理由，給排序」；格式＝「表格，分數＋一句話」。 - 查證清單：背景＝「你是事實查核員」；任務＝「把這篇稿子裡每個可查證的事實列出來，標出哪些有附來源、哪些沒有」；格式＝「清單，沒來源的標紅字提醒」。 - 收斂：「你發現了嗎——skill 不是新東西，它就是你上週學的三段式指令，被存起來、給它取個名字。 差別只在：以前每週重打，現在喊一聲就跑。」 - 轉場到 15′b：「但這裡有個天花板——剛剛的 skill，料是『你貼給它的』。如果料根本不在你資料夾裡、在試算表、在政府開放資料庫呢？這就要講 MCP。」

15′b — 用 MCP 接資料源（用比喻講清楚）

先接回上週的轉接頭比喻（3′） - 喚回上週的一句話：「上週講過 MCP＝轉接頭。今天把它接上去真的用一次。」 - 把比喻講到底：「Claude Code 預設只看得到你 cd 進去的那個資料夾。你資料夾以外的世界——一張 Google 試算表、政府開放資料平台、你的行事曆、一個資料庫——它伸手碰不到。沒 MCP，它是被關在資料夾裡的；插上 MCP，它能伸手到外面把料拿進來。」 - 本質金句：沒接資料源的 skill，再漂亮也只是純文字模板；MCP 是讓它伸手拿到外面真實料的那條手臂。

MCP 能接什麼（4′，舉學生會用到的） - 列幾個管理／編務職真的會碰的料（投影片同步）： - 試算表——你部門的稿件追蹤表、KPI 表、預算表。 - 政府開放資料——做報導／簡報常要抓的公開數據。 - 檔案／資料夾——一整批 PDF、一疊訪談逐字稿。 - 行事曆——把這週會議自動彙整成待辦。 - 對照給學生看差別： - 沒 MCP 的週報 skill：「我每週要先自己把試算表複製貼上，再丟給它。」 - 插上試算表 MCP：「我喊一聲『跑週報』，它自己去那張試算表把這週的列讀出來，直接產週報——我連複製貼上都省了。」

批次產製多版本（5′，這段是管理職的殺手鐧） - 講概念：「同一份素材，不同平台要不同版本——一篇稿子，你要 FB 版、IG 版、LINE 版、電子報版，過去你得手動改四遍。」 - 接到 skill＋MCP：「把『一份素材 → 產出四個平台版本，各自符合該平台字數與語氣』寫成一個 skill，料從 MCP 自動拉進來，喊一聲就一次吐四版。」 - 強調這是「人力 × 平台數」的放大——「你不是省一次，是每篇稿子省四次、每週幾十篇地省。這就是把個人工具放大成部門產能的起點（呼應 Case - GTM Engineering at Anthropic 個人工具 → 產品化 → 分發）。」 - 轉場到 15′c：「概念聽懂了，但真正會懂是手做一次。最後 15 分鐘，每個人挑一件自己每週都做的事，當場做成一個 skill 並跑一次。」

15′c — 動手做自己的 skill（手把手）
  • 宣布任務：「想一件你自己每週都在做、步驟又固定的事——彙整某張表、整理某類信、產某種貼文都行。我們要把它當場做成一個 skill，跑一次，驗收。」
  • 帶領節奏（詳見下方「活動與討論造稿」）：挑事 → 寫三段式 → 存成 skill → 跑一次 → 驗收（對一處／待修一處）。
  • 全程口頭提醒兩句心法：
  • 「三段式裡每留白一處，AI 就替你自作主張一處。」——背景、任務、格式三段都要講死（連到 creativity/prompts 模板）。
  • 「判斷哪步該放手讓它自己跑、哪步該你接手，這個分寸今天一樣是最重要的。」（連到 adaptive autonomy）

② wiki 真實案例 / 引用

  • Case - GTM Engineering at Anthropic — 核心案例，貫穿全堂。Anthropic 一位從沒寫過程式的銷售 Jared Sires，把自己每天重複的工作流做成個人工具、先在自己身上驗證（Slack 貼出 24 小時內被同事採用），再打包成全公司 Sales Plugin、數月內 80% 銷售採用——個人工具 → 驗證 → 產品化 → 分發正是 15′b 「批次產製」與這堂課「把重複爛事固化成 skill」的真實縮影。他的起手式（「找一個拖慢你的任務」）就是 15′c 的活動設計。
  • prompt engineering — 支撐 15′a／15′c 「三段式要講死」與 skill 是迭代調出來的。可引述 Midjourney 平均 7.8 步迭代：好 skill 不是一次寫對，是跑幾次、發現留白、補清楚，慢慢調出來的。
  • adaptive autonomy — 支撐 15′b／15′c 「哪步放手讓 skill 自己跑、哪步你接手」。核心主張：能沿自主刻度滑動比固定的高／低自主更利績效——對應「接了 MCP 自動拉料就放手，但產出仍要你驗收把關」。
  • cognitive offloading — 支撐反思環節：Koh & Doroudi 2023 指出適度卸載釋放認知資源、過度卸載會「沒真正學到」。固化成 skill 是把雜務卸給機器，但哪件事該卸、卸了會不會讓你失去手感仍是人的判斷。
  • creativity/prompts — 15′a／15′c 寫三段式的真實範本：現成「角色設定＋任務＋輸出格式」模板，當「skill 的三段怎麼寫」直接示範。
  • Davenport Mittal 2022 How Generative AI Is Changing Creative Work — 支撐全程心法「人在前後端」：你在前端把流程描述清楚（寫 skill）、在後端驗收修補，skill 自動跑不等於你能撒手。說明設計工作流仍是人機分工，不是全自動。

誠實標註：Claude Code 的 skill 語法、MCP 怎麼接、批次產製的操作步驟，wiki 幾乎沒有素材（新工具尚無論文，屬正常）。因此 15′a 的判準與 worked example、15′b 的 MCP 接法、15′c 的操作流程一律用通用內容＋上述 Case 案例；wiki 引用集中在理論層（人機分工、prompt 迭代、自主校準、認知卸載）。這點與 M Claude Code 上手 完全一致。

④ 活動與討論造稿

活動 A：做自己的第一個 skill（15′c，手把手）

明確步驟（投影同步，老師喊口令、學生跟） 1. 挑事：寫下一件你每週都做、步驟固定的事。口令：「對照投影片 2 三條判準——頻率高嗎？步驟固定嗎？輸入輸出講得清楚嗎？三條都中再往下。」 2. 寫三段式：套 creativity/prompts 模板，把背景、任務、格式三段各寫死——背景講你是誰幫誰、任務把步驟一條條列、格式講輸出長相。口令：「每留白一處，AI 就替你亂填一處。」 3. 存成 skill：給它取個一看就懂的名字，存起來。 4. 跑一次：喊名字、丟料、看它先講計畫再放行（沿用上週「先讀計畫再放行」的驗收動作）。 5. 驗收：結果出來，立刻標記「對一處／待修一處」，並判斷待修的是 prompt（哪段留白了）還是資料（根本沒接到料）。

給學生的提問（邊做邊問） - 「你的三段裡，哪一段最容易偷懶留白？」（預期：多數人任務寫太籠統，或忘了講格式） - 「如果它跑歪了，是 prompt 的問題、還是它根本沒拿到對的料？」（把目標 3 的分析能力逼出來）

常見錯誤（老師預先點名，降焦慮） - prompt 留白讓 AI 自作主張——任務只寫「幫我整理一下」，結果發散；引導句：「回去把任務拆成一條條動詞，把格式講死。」 - 沒接到資料源，只是純文字模板——skill 看起來會跑，但料每次都要你手貼，根本沒省到事；引導句：「這還不是工作流，只是把指令存起來。問問自己：料能不能讓它自己去拿（MCP）？」 - 挑了一件一次性的事做成 skill——白做工；引導句：「skill 的價值在重複，挑你下週、下下週還會再做的。」 - 期待一次到位——提醒 prompt engineering 的 7.8 步迭代，「skill 是跑幾次調出來的，不是一次寫對。」

活動 B：配對互評與全班收斂（既有討論段落，造稿細化）

配對互評（~5′） - 口令：「兩人互看對方剛做的 skill，問三件事——解決的是哪個會重複很多次的工作？prompt 寫得夠死、別人照跑會不會跑歪？有沒有真的接到資料源，還是只是純文字模板？」 - 引導句：「第三題最關鍵——很多人做出來的其實只是『把指令存起來』，料還是手貼。真正的工作流，是料能自己流進來。」

全班收斂一題（~3′） - 老師收集舉手場景，板書「最值得做成 skill 的工作類型」，貼上班級工具箱。 - 用三條判準現場篩：把同學丟出的場景一個個對「頻率高／步驟固定／輸入輸出可描述」三欄打勾，篩掉不適合的。

寫下個人反思（~2′） - 既有題目：「我下週會把哪一件每週都在做的事，包成自己的第一個 skill？」並標出它最可能卡住的地方（prompt 還是資料接不上）。 - 引導扣回理論：用 cognitive offloading 提醒——「把重複雜務卸成 skill 沒問題，但判斷與選題的部分留給自己，不然你會連它跑歪了都看不出來。」

小作業（既有，再次口頭強調）
